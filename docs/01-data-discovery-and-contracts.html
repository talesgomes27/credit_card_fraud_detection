Documento técnico de auditoria preliminar (Ask preliminar & Prepare) para o projeto de detecção de fraudes em transações de cartão de crédito. Base de dados auditada: credit_card_fraud_detection_2026.csv.

1 1. Contexto de Negócio e Síntese Inicial (Ask Preliminar)

Sistemas legados de detecção de fraude frequentemente enfrentam dois gargalos: datasets públicos excessivamente anonimizados (como o clássico Kaggle 2013 com variáveis PCA V1 a V28) e a falta de interpretabilidade para regras de negócio operacionais.

O dataset inspecionado resolve essa limitação. Ele disponibiliza 43 variáveis com nomes funcionais diretos e distribuições calibradas contra relatórios de referência da indústria: - Federal Reserve Payments Study (2023) - Nilson Report (2023) - FICO Falcon Fraud Manager Benchmarks - European Central Bank Card Fraud Report (2022) - TransUnion Global Fraud and Identity Report (2023)

O problema analítico abrange três camadas com níveis distintos de complexidade: 1. Detecção Binária (is_fraud): Decisão transacional em tempo real (fraude vs. legítima), com classe minoritária severamente desbalanceada (~2,06%). 2. Tipificação de Fraude (fraud_type): Classificação multiclasse em 5 categorias (Legítima, Card-Not-Present, Account-Takeover, Synthetic-Identity, Card-Present). 3. Quantificação de Perda Financeira (fraud_amount_lost): Estimação de valor residual não recuperado após estorno parcial (zero-inflated continuous).

2 2. Diagnóstico da Fonte e Profiling Estatístico (Fase Prepare)

2.1 2.1 Metadados e Volumetria Geral

A inspeção direta do arquivo credit_card_fraud_detection_2026.csv confirmou: - Linhas: 100.000 registros. - Colunas: 43 atributos (40 explicativos e 3 variáveis target). - Duplicatas exatas: 0 linhas. - Duplicatas de transaction_id: 0 linhas. - Tamanho do arquivo em disco: 25,7 MB. - Clientes únicos (customer_id): 8.000 clientes. - Cartões únicos (card_id): 8.000 cartões (relação exata de 1 cartão por cliente). - Lojistas únicos (merchant_id): 3.000 estabelecimentos. - Janela temporal real (transaction_datetime): 2026-01-01 02:28:51 até 2026-12-31 23:45:47 (ano fiscal 2026 completo, apesar da menção histórica a 2024 no texto descritivo do about.txt).

2.2 2.2 Auditoria Crítica: Tratamento de 'N/A' na Coluna browser

O parser padrão de bibliotecas como pandas (pd.read_csv) inclui a string 'N/A' na lista default de valores nulos (_NA_VALUES). Quando o CSV é carregado sem parâmetros adicionais, pandas marca 41.709 registros como NaN na coluna browser.

Essa conversão é um falso positivo de ausência de dados. A análise cruzada entre canais de transação e navegadores demonstra que o valor 'N/A' é uma categoria válida do domínio:

Canal (transaction_channel) App Chrome Edge Firefox N/A Other Safari Total
ATM 0 0 0 0 5.932 0 0 5.932
In-store 0 0 0 0 35.777 0 0 35.777
Mobile App 12.759 0 0 0 0 0 0 12.759
Online 0 20.359 4.544 5.448 0 2.340 12.841 45.532
Total Geral 12.759 20.359 4.544 5.448 41.709 2.340 12.841 100.000

Transações físicas presenciais (In-store) e operações em terminais de autoatendimento (ATM) não utilizam navegador web. Por definição, não possuem browser. Tratar esses registros como missing desnecessário gera erros em imputações automáticas. Regra obrigatória de leitura no pipeline: carregar o CSV com keep_default_na=False ou mapear explicitamente na_values=[''] para manter 'N/A' como categoria literal estruturada ('Not Applicable').

2.3 2.3 Auditoria Temporal e Inversão em 28/02/2026

O dataset está quase totalmente ordenado cronologicamente, com uma única exceção identificada entre as linhas 16220 e 16221: - Linha 16220: TXN-00016221 em 2026-02-28 23:56:58 - Linha 16221: TXN-00016222 em 2026-02-28 00:21:25

O dia 28 de fevereiro de 2026 contém 579 transações particionadas em dois blocos sequenciais concatenados. Para garantir o particionamento temporal rigoroso no Gate 3 e Gate 5, o carregamento inicial deve executar ordenação estável por transaction_datetime.

5 5. Análise de Risco de Data Leakage e Estratégia de Partição

5.1 5.1 Isolamento Rigoroso entre Targets

As três variáveis target possuem dependência determinística: - fraud_amount_lost é maior que zero se, e somente se, is_fraud == 1. - fraud_type é diferente de 'Legitimate' se, e somente se, is_fraud == 1. - Não existem contradições lógicas na base: 0 inconsistências detectadas em 100.000 linhas.

Contrato de isolamento de features: 1. Nenhum modelo treinado para estimar is_fraud pode receber fraud_type ou fraud_amount_lost. 2. Modelos preditivos de fraud_type ou de perda financeira devem operar sob arquitetura desacoplada (classificação direta com exclusão mútua das outras targets ou arquitetura em dois estágios / modelo hurdle).

5.2 5.2 Exclusão de Identificadores Puros e Redundâncias

  • transaction_id: chave sequencial unívoca sem poder generalizável. Exclusão mandatória.
  • card_id: possui mapeamento bijetor com customer_id (CRD-XXXX coincide com CUS-XXXX). Não agrega valor analítico. Exclusão mandatória.
  • customer_id: alta cardinalidade (8.000 IDs). Se mantido cru, gera memorização indevida de histórico por cliente em vez de padrões generalizáveis de fraude.

5.3 5.3 Vazamento Temporal e Estrutura de Clientes

A análise de dispersão temporal revelou que os clientes realizam transações distribuídas ao longo de todo o ano. A janela média de atividade por cliente é de 307 dias. Além disso, certas features de perfil e comportamento (avg_transaction_amount_30d, std_transaction_amount_30d, credit_score, account_age_days, num_chargebacks_ever) são estáticas por cliente na base.

Impacto arquitetural: - Uma validação aleatória cruzada (K-Fold clássico) misturaria transações do mesmo cliente no treino e teste. O modelo aprenderia a memorizar perfis de clientes específicos em vez de detectar anomalias transacionais. - Para simular a produção de um motor antifraude bancário, a validação deve adotar Time-Ordered Split (divisão temporal out-of-time): - Treino: Transações cronológicas de Janeiro a Agosto de 2026 (~66.800 transações). - Validação: Transações de Setembro a Outubro de 2026 (~16.900 transações). - Teste Cego: Transações de Novembro a Dezembro de 2026 (~16.300 transações).

6.3 Contrato 3: Limites Numéricos e Invariantes Físicas

range_and_invariance_contract:
  ranges:
    transaction_amount: { min: 0.50, max: 20000.00 }
    transaction_hour: { min: 0, max: 23 }
    customer_age: { min: 18, max: 100 }
    credit_score: { min: 300, max: 850 }
    credit_limit: { min: 500.00, max: 50000.00 }
    amount_vs_avg_ratio: { min: 0.0, max: 1000.0 }
    transactions_last_1h: { min: 0, max: 20 }
    fraud_amount_lost: { min: 0.0, max: 15000.00 }
  invariants:
    # 1. Regra de presença física do cartão
    - condition: "card_present == 1"
      must_match: "transaction_channel == 'In-store' and device_type == 'POS Terminal' and browser == 'N/A'"
    # 2. Regra de ATM
    - condition: "transaction_channel == 'ATM'"
      must_match: "device_type == 'ATM' and browser == 'N/A' and card_present == 0"
    # 3. Consistência entre canais móveis e browser
    - condition: "transaction_channel == 'Mobile App'"
      must_match: "browser == 'App' and device_type == 'Mobile'"
    # 4. Consistência de alvos de fraude
    - condition: "is_fraud == 0"
      must_match: "fraud_type == 'Legitimate' and fraud_amount_lost == 0.0"
    - condition: "is_fraud == 1"
      must_match: "fraud_type != 'Legitimate' and fraud_amount_lost > 0.0"
    # 5. Regra de país de alto risco
    - condition: "high_risk_country == 1"
      must_match: "merchant_country in ['China', 'Nigeria', 'Romania', 'Russia']"
    # 6. Regra de transação internacional
    - condition: "international_transaction == 1"
      must_match: "merchant_country != 'USA'"

7 7. Conclusão do Gate 1 e Próximos Passos

A base credit_card_fraud_detection_2026.csv possui consistência estrutural impecável, livre de ruídos acidentais e aderente aos benchmarks econômicos da literatura. O principal ponto de atenção técnica na ingestão é a preservação de 'N/A' como string válida na coluna browser.

Com este diagnóstico concluído e contratualizado, o projeto cumpre os requisitos de entrada para a transição ao Gate 2 (Ideação, Escopo, Hipóteses e Especificação).
